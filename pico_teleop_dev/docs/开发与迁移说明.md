# 开发与迁移说明

## 整理范围

2026-10-20从 `RM/pico_xr` 与 `RM/camera` 整理后，再按日常使用范围裁剪。运行代码位于仓库根目录，开发与维护材料集中到 `pico_teleop_dev/`。旧 `RM` 目录、原始数据、已有导出和接收容器保留。

运行代码集中到 `app/`，日常根目录仅README、采集脚本、导出脚本、configs和app。当前配置保留5份；历史配置和维护姿态移到开发目录。旧的按Grip分段录制器退出正式运行路径，数据组装函数独立为 `control_sample.py`；原右臂调试入口移除，保持双臂共用的SDK后端提取为 `robot_backend.py`。普通双臂遥操的监督入口移到开发维护工具中。

遥操数学、速度、轨迹整形、夹爪控制和B+Y退出行为沿用已确认版本。Grip过渡修复集中在离线转换和汇总，精简不改变控制器或相机行为。

## 运行环境和共享资源

- 控制Python默认使用相邻 `RM/.venv/bin/python`，不升级已有SDK环境。可以用 `PICO_CONTROL_PYTHON` 指定迁移机环境。
- 相机Python仍由 `configs/collection.json` 指向 `/usr/bin/python3`，其中已有RealSense、OpenCV和GStreamer依赖。
- 接收器默认沿用相邻 `RM/pico_xr/state/pico.sock`；开发目录的 `start_receiver.sh` 验证已有容器挂载，挂载不匹配时明确报错，不自动替换运行中的容器。
- 新旧代码共用 `RM/.single_joint_step.lock`、`RM/.pico_left.lock` 和 `RM/.pico_right.lock`，避免两套入口同时控制同一机械臂。
- `PICO_ROBOT_ROOT`、`PICO_RECEIVER_STATE_DIR`、`PICO_RECEIVER_SOCKET` 用于显式调整部署路径。调整接收地址时同步核对采集配置中的 `receiver_socket`。
- raw仍写到共同的 `data/pico_raw`。运行目录不使用源码或配置链接，配置统一从 `configs` 读取，诊断状态写入 `app/state`。开发目录的5份当前配置以相对链接指向运行配置，避免修改出现两份分叉。
- 两套导出镜像继续使用已冻结的 `pico-export:v21` 和 `pico-export:v30`。导出入口显式选择本项目源码，源只读挂载、容器禁网，输出必须为新目录。

构建文件分别在 `pico_teleop_dev/environment/receiver/Dockerfile` 和 `pico_teleop_dev/environment/export/Dockerfile`，构建上下文为两个目录共同的父目录，命令见开发目录README。LeRobot固定版本、依赖及源归档保存在开发目录，运行端只保留校验所需的 `app/export_source_pins.json`，无需把LeRobot安装到控制环境。

运行入口只把 `app` 加入Python搜索路径，不依赖开发工具。迁移时仍需准备机械臂SDK控制环境、相机系统依赖、PICO接收服务和两种导出镜像，并按目标机器修改相机序列号、网络和路径配置；运行文件夹本身不包含这些已安装环境。

精简前完整快照及运行验证报告保留在本机的 `archive/` 和 `reports/`，不纳入公开仓库；历史清单仅描述精简前布局。

## 录制边界修复与动作来源

以下是本项目的转换策略，不是LeRobot格式规定的质量门限。原始A边界不变，仍按完整30Hz网格生成，不裁剪过渡帧、不压缩时间，也不修改原始记录。

1. 持续发送运动时，动作仍取实际成功发送的、时间不晚于采样点的关节位置目标。
2. 已松开Grip且反馈静止时，沿用实际反馈保持，标记为 `derived_hold`。
3. Grip刚接管、尚未发送新目标且反馈静止时，取实际反馈作为位置保持表示，标记为 `derived_anchor_hold`。
4. 松Grip或正常发送门控停止后，停止请求已由软件确认且晚于最后运动指令时，允许物理减速尚未结束。以新鲜实际反馈作为**派生的位置保持动作**，标记为 `derived_stop_hold`。它不声称该位置曾作为指令发送，也不声称机械臂已经完全停稳，且不沿用已取消的旧运动目标。
5. 夹爪在线、有有效反馈、从未尝试或接受过开合命令、也无待发命令或故障时，以实际开口表示保持，标记为 `derived_uncommanded_hold`。这允许只操作一侧，不要求另一侧为了采集而额外开合。已尝试但失败、命令待发、ACK在未来或故障状态不会走此分支。
6. 关节反馈、夹爪反馈和夹爪ACK按各自的主机接收时间选择，控制状态按遥测时间选择。较晚遥测行中携带的较早反馈可以使用，但反馈本身的时间不得晚于采样点。这样避免把“遥测装包较晚”误当成反馈超时。

50ms图像/反馈/遥测门限与250ms夹爪反馈门限保留。未确认停止、活动中的软暂停/未知状态、真实缺失或超时、损坏图像、删除和中断记录仍会拒绝。修复没有修改遥操发送或停止接口。

`provenance.jsonl` 为每个采样点保留控制遥测序号、实际反馈序号/接收时间、动作来源、停止确认时间和夹爪来源。导出manifest写入 `sampling_revision=20261020_independent_feedback_and_stop_hold` 及派生动作定义。旧的拒绝策略可显式设置 `release_action=reject_until_stationary`、`gripper_without_target=reject` 复查。

派生位置保持适用于当前14维位置动作约定。训练读取时应保留并审查这些来源标记；它们不代表重新构造出一条不存在的硬件位置指令。

## 验证与仍待现场确认的项目

运行离线测试：`bash ./run_tests.sh`。本机验证报告、遥操状态和原始数据不会纳入公开仓库。`legacy_recording.py` 仅保留历史录制测试，不会由正式入口导入。

第2项“头显视频独立于采集启动”按用户要求暂缓，当前显示服务仍随采集启动。项目机的相机保护膜、视野与夹爪尖端可见性、真实分拣、显示延迟及迁移配置仍需现场验收。已有原始记录的离线转换检查通过，不等于已完成这些实机验收。
